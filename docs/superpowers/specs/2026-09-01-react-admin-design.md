# React 车辆后台管理设计

## 目标

为现有 `fastapi-scaffold` FastAPI 项目新增独立的 React 后台管理前端。管理员登录后可以维护汽车品牌和车型；首版不提供访客浏览、普通用户注册或数据看板。

## 范围与约束

- 前端使用 React、TypeScript 与 Vite 构建，放在仓库根目录的 `react-admin` 目录。
- 采用轻量自建界面，不引入 Ant Design 等大型组件库。
- 只对接既有的 `/auth/login`、`/brands` 和 `/car-models` 接口；后端无需修改。
- 开发环境通过 Vite 代理转发 `/api` 请求到 `http://127.0.0.1:8000`，避免跨域问题。
- 生产部署时由环境变量配置 API 地址。

## 页面与交互

### 登录页

登录页包含用户名、密码和提交按钮。成功后保存 JWT，进入品牌管理页；失败时显示后端返回的可读错误信息。已登录用户再次访问登录页时直接进入管理页。

### 主布局

主布局由顶部栏、左侧导航和内容区组成。顶部栏显示「管理员后台」和退出按钮；左侧导航提供「品牌管理」与「车型管理」。退出时删除本地 JWT 并返回登录页。

### 品牌管理

表格展示名称、国家、描述和操作。新增及编辑使用同一弹窗表单，字段为名称、国家、描述；删除操作需要二次确认。请求成功后刷新表格，失败时保留当前表单并显示错误。

### 车型管理

表格展示名称、所属品牌、年份、价格和操作。页面顶部提供品牌筛选。新增及编辑弹窗包含名称、品牌、年份、价格字段，品牌选项来自品牌列表；删除操作需要二次确认。价格按后端响应值展示，不在前端自行换算单位。

## 架构与数据流

界面按职责拆分：`pages` 承担页面编排，`components` 负责表格、弹窗和通用界面，`api` 集中封装 HTTP 请求，`auth` 负责 JWT 持久化与会话状态，`types` 定义与后端请求/响应一致的 TypeScript 类型。

请求客户端自动读取 JWT，并为受保护请求设置 `Authorization: Bearer <token>`。遇到 `401` 时清除本地会话并跳转登录页；`403`、`404`、`409`、`422` 和网络错误转换成可展示的中文提示。品牌与车型的每次成功写入后重新拉取当前表格，保证界面状态与后端一致。

## API 映射

| 界面动作 | 后端接口 |
| --- | --- |
| 登录 | `POST /auth/login` |
| 查询、新增、编辑、删除品牌 | `GET`、`POST`、`PUT`、`DELETE /brands` |
| 查询、新增、编辑、删除车型 | `GET`、`POST`、`PUT`、`DELETE /car-models` |
| 车型按品牌筛选 | `GET /car-models?brand_id={id}` |

## 错误处理

- 登录失败或凭证失效：提示用户，并返回登录页。
- 字段校验失败：展示后端错误信息，不清空用户输入。
- 删除有关联车型的品牌：展示后端业务错误，不刷新表格。
- 网络不可用或服务未启动：显示连接失败提示，并允许用户重新尝试。

## 测试与验收

使用 Vitest 与 React Testing Library 测试请求客户端、登录状态和关键表单行为。实现采用测试先行：先验证测试因缺少行为而失败，再完成最小实现。验收时执行前端测试和生产构建，并启动 FastAPI 服务后完成一次登录及品牌、车型 CRUD 的人工联调。

## 非目标

首版不包含用户注册、权限角色切换、仪表盘统计、文件上传、批量导入导出、分页 UI 或移动端专门布局。
